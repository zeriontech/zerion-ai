# __APP_NAME__

A private-payments app on Solana, powered by Umbra. Sender deposits
funds into a shielded pool and creates a receiver-claimable UTXO; the
recipient scans + claims it from a different wallet. Source and
destination addresses are unlinkable on-chain.

This scaffold was generated by the `umbra-sdk` Claude Code skill.
It targets the **__NETWORK__** Solana cluster and follows all 10
Umbra SDK critical rules out of the box.

## Quick start

```bash
cp .env.example .env.local
# edit .env.local — set NEXT_PUBLIC_RPC_URL to a paid Solana RPC
npm install
npm run dev
```

Open http://localhost:3000, connect a Solana wallet, then walk:

1. **/account** — register on Umbra (one-time per wallet, idempotent)
2. **/send** — deposit + create a receiver-claimable UTXO
3. **/receive** — scan + claim received UTXOs

## What the app does

- **Master-seed derivation**: re-derived every session by signing the
  Umbra magic message. Zero persistence, zero attack surface. The user
  sees one extra signature prompt per visit.
- **Privacy default**: Tier 1 (ETA→ETA) when both sides are registered,
  Tier 2 (ATA→ETA) for first-time recipients. Receiver-claimable for
  natural timing separation.
- **Scan cursor**: persisted in IndexedDB per address; resumes
  incrementally across reloads.
- **Claim retries**: idempotent via `request_id` + on-chain nullifier
  check. `DUPLICATE_OFFSET` 409 treated as success.
- **No deep imports**: only the four documented sub-paths
  (`@umbra-privacy/sdk`, `/types`, `/constants`, `/errors`).

## Project layout

- `app/` — Next.js App Router pages.
  - `providers.tsx` — `UmbraClientProvider` keyed by connected wallet.
  - `account/page.tsx` — wallet connect + Umbra registration.
  - `send/page.tsx` — deposit + create UTXO flow.
  - `receive/page.tsx` — scan worker + claim queue UI.
- `lib/`
  - `env.ts` — zod-validated env loader.
  - `signer.ts` — Wallet Standard → `IUmbraSigner` adapter.
  - `umbra-client.ts` — `getUmbraClient` factory. Master-seed handling
    is inlined here via the `masterSeedStorage` injection (in-memory
    by default; re-derived every session). See `advanced.md §3` for
    the override pattern.
  - `scan-cursor.ts` — IndexedDB cursor `(treeIndex, insertionIndex)`
    per address.
  - `claim-queue.ts` — idempotent claim wrapper.
  - `zk-prover.ts` — per-circuit prover loaders (CDN assets).
- `components/`
  - `WalletButton.tsx` — Wallet Standard connect UI.
  - `RegistrationGate.tsx` — blocks send/receive until registered.
  - `PrivacyTierBadge.tsx` — Tier 1/2/3 indicator.
  - `ScanWorker.tsx` — background scan loop.

## Mainnet checklist

Before deploying to a domain real users will see, walk every box in
the project's `MAINNET-CHECKLIST.md` (printed in chat at scaffold
time). Highlights:

- Pinned SDK versions in `package.json` (no `^`).
- Paid Solana RPC, not the free public endpoint.
- Tested register → deposit → create → scan → claim end-to-end on
  devnet first.
- Tested claim retry: kill the tab mid-claim, reopen, no double-claim.
- Wallet swap re-keys the client (`UmbraClientProvider` in
  `app/providers.tsx`).
- ZK prover assets resolve under your CSP (or self-hosted).

## Security notes

- **Master-seed** is currently re-derived every session (no persistence).
  If you want to skip the per-session signature, override the
  `masterSeedStorage` injected into `getUmbraClient` in
  `lib/umbra-client.ts` with an encrypted-at-rest implementation. See
  the skill's `reference/advanced.md` §3 for the override pattern and
  `reference/pitfalls.md` §7 for the pitfalls.
- **Same-wallet round-trip** is blocked in `lib/claim-queue.ts`.
  Claiming back to the source ATA refuses to sign.
- **`optionalData`** is rejected unless it's a 32-byte pre-hashed value.
  The skill's `reference/pitfalls.md` §5 explains why.
